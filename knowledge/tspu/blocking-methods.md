# Методы блокировки ТСПУ

## Типы блокировки (DPI behavior)

| Behavior | Действие | Протоколы |
|----------|----------|-----------|
| **block** | Блокировка трафика | HTTP → 302 redirect, HTTPS → TCP RST или silent drop |
| **ignore** | Распознать, но пропустить (для двухстадийной блокировки) | Все |
| **redirect** | HTTP-редирект на страницу-заглушку | Только HTTP |
| **color** | Пометить трафик (для мониторинга) | Все |

## HTTP-блокировка
- Фильтр отправляет **302 Redirect** на страницу-заглушку (redirect URL в конфиге)
- Может блокировать **конкретный URL**, не только домен
- Заглушка показывает причину блокировки

## HTTPS-блокировка
Два режима:
- **TCP Reset**: фильтр отправляет RST обоим сторонам → клиент видит "Connection reset"
- **Silent drop** (`send RST off`): пакеты просто отбрасываются → клиент видит timeout

**`send RST off`** — критический параметр. Когда включён, приложения бесконечно пытаются переподключиться (нет явного отказа). Когда выключен — отправляется RST, что является явным сигналом блокировки.

## Деградация протоколов (capacity)

ТСПУ может **частично** блокировать протокол, дропая пакеты с заданной вероятностью:

```
capacity = 0    → полная блокировка (все пакеты дропаются)
capacity = 2-10 → эффективная деградация (98-90% пакетов дропается)
capacity = 100  → полный пропуск (все пакеты проходят)
```

**Эффект деградации при capacity 2-10%**:
- Голосовые вызовы (VoIP) — рвутся
- Видео — бесконечная буферизация
- Мессенджеры — сообщения не отправляются
- Веб-страницы — очень медленная загрузка или timeout

Это коварнее полной блокировки: пользователь думает что проблема с интернетом, а не с цензурой.

## DPI-листы (0-15)

Фильтр поддерживает до 16 независимых DPI-листов, каждый со своим поведением:

- **Лист 0**: обычно для распознавания (behavior: ignore)
- **Лист 5**: обычно для блокировки (behavior: block)
- Реестр РКН загружается в отдельный лист

**Формат списков**:
- IP-адреса и подсети: `1.2.3.4`, `1.2.3.0/24`
- Диапазоны IP: `1.2.3.4-1.2.3.10`
- URL (HTTP): `http://example.com/path`
- Домены (HTTPS): `example.com`, `*.example.com`

## QUIC-блокировка

QUIC обрабатывается через отдельный QUIC list в DPI-листе. QUIC сложнее для DPI:
- Зашифрован с первого пакета
- UDP-based — нет TCP handshake для перехвата
- SNI в QUIC Initial может быть зашифрован (ECH)

## Что это значит для bypass

### Диагностика типа блокировки
- **Connection reset** → HTTPS block с RST → DPI активен, можно обойти
- **Timeout без RST** → Silent drop (`send RST off`) → DPI активен, можно обойти
- **Redirect на заглушку** → HTTP block → DPI активен, можно обойти
- **Timeout + TCP SYN не проходит** → IP block (Eco Highway) → нужен VPN

### Деградация vs блокировка
Если сайт работает, но очень медленно — возможна деградация протокола. Стратегии bypass помогают и в этом случае, потому что DPI перестаёт распознавать протокол → capacity не применяется.

### Множественные DPI-листы
Ресурс может быть в нескольких листах одновременно. `blockcheckw status` поможет определить тип блокировки до начала подбора стратегий.
